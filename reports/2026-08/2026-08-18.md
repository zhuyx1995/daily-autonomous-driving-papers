## 1. Not All History Helps: Velocity-Aware Selective Memory for Long-Horizon End-to-End Autonomous Driving

- arXiv： [arXiv:2608.15573](https://arxiv.org/abs/2608.15573)
- 首次提交：2026-08-16

**研究问题**
- 端到端自动驾驶里的长时域规划很依赖历史规划状态作为时间上下文，但“模型自己上一个周期预测出来的历史”并不总是可靠：一旦运动阶段切换，旧历史就可能变成过时甚至冲突的先验。
- 这会直接拖累 4-6 秒长时域规划的稳定性，尤其是在交通状态持续演化、纵向动作阶段频繁变化的场景里，历史记忆到底该保留多少、何时该抑制，一直是端到端规划里的真实问题。

**核心方法总结**
- 论文提出 **StableDrive**，核心是一个 **Selective Momentum Memory (SMM)** 机制，用 Mamba 风格的 selective state-space operator 控制“上一个自预测规划状态”对当前周期的影响强度。
- 作者同时设计了 **Motion-Stage Training Scaffold (MSTS)**，在训练阶段显式加入 motion stage、长时域轨迹和纵向运动监督，帮助模型学会分辨不同运动阶段下该保留什么、该忘掉什么；该 scaffold 在推理时移除，不额外增加部署成本。
- 论文还通过两个对齐端点之间的固定参数中点构造单一可部署规划器，避免 ensemble 或额外测试时计算，让方法更偏工程可用而不是只在训练图里好看。
- 摘要结果显示，它在 **nuScenes / LT-nuScenes / NAVSIM v1/v2** 上都刷新了多个规划指标，尤其对碰撞率、TPC 和 L2 改善明显，和自动驾驶主线的端到端规划问题高度对齐。

**一句话摘要**

## 2. MM-BEV: Enhancing Timeliness by Computing Where and When it Matters

- arXiv： [arXiv:2608.15437](https://arxiv.org/abs/2608.15437)
- 首次提交：2026-08-15

**研究问题**
- 多模态 BEV 感知通常把 LiDAR 的几何精度和相机的密集语义结合起来，但真正落地到车端时，算力、传感器不同步和时延预算才是最容易把系统卡死的地方。
- 许多现有方法只是在 detector 本身上做轻量化，却忽略了更关键的系统级问题：不是所有区域都同等重要，不是所有时刻都需要同样高的感知开销，而且很多检测目标其实并不会立刻影响规划决策。

**核心方法总结**
- 论文提出 **MM-BEV**，核心原则是 **compute where and when it matters**：把感知工作拆成“安全关键、必须优先完成”的 mandatory work 与“可降级、可裁剪”的 optional work。
- 方法通过四个部件协同工作：基于历史检测和运动外推的 **criticality-ranked temporal ROI selector**、面向 ROI 的稀疏相机 / LiDAR 特征提取、根据场景动态和 TTC 自适应调整模态时序的 **latency-aware coordinator**，以及把 sensing 与 inference 解耦的 **asynchronous scheduler**。
- 这种设计不只是压缩 backbone，而是直接把“目标危险度、制动距离、TTC、帧是否过时”引入系统调度，让多模态 BEV 感知真正和自动驾驶实时性约束绑定起来。
- 摘要结果显示，它在 **nuScenes** 上把 inference latency 降到原来的 **1/1.96**、端到端时延降到原来的 **1/2.93**，同时几乎不损失 safety-critical recall；在搭载 Jetson AGX Orin 的实车平台上也有明显时延收益。

**一句话摘要**
